# Designing from references

This skill owns what to take from material a brief supplies. What the result should look
like belongs to `design-point-of-view` and the other design skills.

**[DFR-1]** An existing prototype's flow is decided. Keep its screens, steps, behaviour,
states and content. A visual pass changes how they're presented, and any flow problem you
notice gets reported instead of fixed. List the screens and states before starting, and
check that every one still works afterwards.

**[DFR-2]** Treat inspiration as qualities, not layouts. Name what each image does, such
as how extreme its type contrast is, how dense it feels, how it spends colour, and its
shape language. Translate those qualities onto this project's own content. Don't copy its
layout, brand, copy or assets.

**[DFR-3]** With several inspiration images, find what they share. Write down the qualities
you're taking, and from which image, before building. Where they conflict, choose one
direction instead of averaging them.

**[DFR-4]** Compare the result with each reference at the same width, side by side and
blurred (`DSC-2`). Ask whether the named qualities came through, not whether the pages match.

**[DFR-5]** Don't invent brand assets. If a logo, typeface or brand colour is named but not
supplied, ask for it once before starting. Then use a clearly marked stand-in and name it.
